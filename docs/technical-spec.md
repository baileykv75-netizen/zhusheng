# 「筑生」建筑全生命周期智能体技术说明

## 1. 项目摘要

“筑生”为每栋建筑创建一个贯穿设计、建造、交付与运营的建筑总智能体。它通过长期建筑记忆连接建造期和入住期：建造时协助工友完成可信留痕与质量协同；入住后结合传感器、设备接口和专业智能体，为住户、物业及企业持续服务。

项目不等同于渗漏助手。原型选择“1602卫生间渗漏”作为唯一纵向样板，用一条可验证链路证明总体架构能够运行：

> 工友参与建造 → 建筑形成记忆 → 住户获得服务 → 设备产生行动 → 企业持续改进

## 2. 主题对应

### 为人民建好房

- 建造质量不仅在交付时验收，还能在使用阶段持续查询和验证。
- 入住问题能够结合真实施工证据定位，减少盲目拆除和漫长沟通。
- 处理结果回流设计、材料和工艺，降低同类问题在后续项目重复发生的概率。

### 为工友谋幸福

- 工友用扫码、语音和照片替代重复填写多个系统表单。
- 每条施工证据自动关联空间、材料和验收要求，减少返工和责任争议。
- 关键工序贡献进入建筑长期记忆，为技能成长和优秀班组评价提供依据。
- 系统只记录必要的班组和资质信息，不公开工友个人敏感信息。

## 3. 系统架构

### 建筑总智能体

每栋建筑具有唯一身份和总智能体。总智能体只负责：

1. 保存跨阶段的长期记忆；
2. 将任务分配给专业智能体；
3. 处理多方目标、权限和行动影响；
4. 向项目、物业和集团管理者形成结构化摘要。

### 专业智能体

建造期能力包括品质智能体、项目协同智能体和工友服务智能体；入住期能力包括建筑健康智能体、设备具身智能体和居住服务智能体。

当前原型只实现总智能体及与样板案例有关的三项专业能力：

- 品质智能体：查询材料、管线、防水和闭水试验证据；
- 建筑健康智能体：分析湿度、流量和空间关系；
- 设备具身智能体：在获得授权后操作模拟阀门并生成设备结果。

### 建筑生命记忆

原型统一表达以下数据：

- `BuildingMemory`：建筑、空间、构件、工序和运营记录；
- `EvidenceRecord`：工友提交、检验记录、图片和来源状态；
- `AgentTask`：总智能体向专业智能体分配的目标与结果；
- `PhysicalAction`：设备动作、风险等级、授权人及执行状态；
- `LifecycleFeedback`：入住事件对后续设计与施工的改进建议。

### 具身执行与人类授权

传感器是建筑的感觉，BIM与建造记录是身体地图和长期记忆，专业智能体负责判断，总智能体负责协调，阀门等设备负责执行。

原型采用三级动作规则：

- 低影响：资料查询、提示和诊断可自动完成；
- 中影响：局部关阀必须由住户或物业授权；
- 高影响：主阀、入户和关键设备动作必须转物业或人工处置。

## 4. 样板链路

### 建造阶段

1. 工友扫描 `MIC-BATH-1602` 卫浴模块。
2. 通过语音和照片提交管线接头、防水和闭水试验记录。
3. 品质智能体检查记录完整性。
4. 建筑总智能体将记录关联到空间、材料、班组和构件身份。

### 入住阶段

1. 墙体湿度持续高于动态阈值，建筑健康智能体创建事件。
2. 总智能体调用品质智能体读取建造期证据。
3. 住户补充停用水后的水表状态与墙面照片。
4. 系统排除洗浴短时潮湿，将疑似漏点定位到管线接头。
5. 总智能体提出关闭局部阀门，并等待明确授权。
6. 设备具身智能体执行模拟关阀，物业同步收到精准工单。
7. 维修完成后继续验证湿度趋势，异常未消失时不得关闭事件。
8. 最终原因写回建筑记忆，并形成后续MiC模块工艺建议。

|---|---|---|
| GET | `/api/state` | 获取完整演示状态 |

| GET | `/api/demo/status` | 查询七步引导演示进度 |

| POST | `/api/demo/reset` | 恢复到引导演示第一步 |

## 6. AI协同与纠偏

- 产品预留兼容式模型接口，通过 `AI_BASE_URL`、`AI_MODEL` 和 `AI_API_KEY` 配置。
- 未配置模型时明确显示“演示回退”，模型失败时显示“安全回退”，不伪装为真实AI在线。
- AI只负责工友口述整理、解释生成和任务建议；返回结果必须是经过字段校验的JSON对象。
- 总智能体不会把单次传感器升高直接判断为渗漏。
- 证据不足时，系统明确列出缺失信息并降低可信度。
- 专业智能体结论通过总智能体合并，冲突时转人工复核。
- 所有判断引用具体施工证据、空间关系或传感器时序。
- 所有设备动作记录请求者、授权人、目标设备和执行结果。
- 维修后必须继续观察传感器回落，形成“行动—验证”闭环。

原型中的风险计算和事件状态采用确定性状态机，语言模型负责解释、规划和交互。真实项目中，安全相关设备控制不由大模型直接决定。

`AgentTrace`记录任务发起者、执行智能体、输入证据、输出、可信度、运行模式和状态。集团管理端可查看协作轨迹，但不会暴露不必要的个人信息。

## 7. 原型说明

原型由 Node.js 内置 HTTP 服务和无第三方依赖的响应式网页组成，可在普通电脑离线运行。

四个界面分别是：

1. 建筑生命主页：先解释总体架构；
2. 工友记录端：展示建造记忆如何形成；
3. 住户服务端：完成渗漏样板闭环；
4. 集团管理端：展示审计记录、工单和跨项目反馈。

系统同时提供七步引导演示和自由探索。引导模式支持下一步、上一步、重置与退出；上一步通过重放已完成步骤恢复一致状态，避免回滚产生残留数据。

传感器、智能阀门和维修过程采用可复现的模拟数据，不宣称已经接入真实住宅设备。

## 8. 试点建议

第一阶段选择一个MiC卫生间模块或样板间，打通房间码、管线数据、防水与闭水记录。

第二阶段接入湿度、流量和局部阀门，验证异常识别、授权机制和精准工单。

第三阶段接入项目与物业系统，观察工友记录耗时、证据完整度、问题定位时间和维修复发率。

## 9. 边界

- 作品主体是建筑全生命周期总智能体，渗漏只是样板。
- 不开发机器人本体，只提供具身设备任务和标准接口。
- 不在本次原型展开养老、节能、安防等第二案例。
- 不以试点目标冒充已经取得的经营成效。
- 不宣称“全国首创”，表述为从数字建造向建筑具身智能延伸的创新探索。
