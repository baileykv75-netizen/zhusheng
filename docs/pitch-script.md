# 「筑生」5分钟路演稿

## 0:00–0:25｜一句话定义

各位评委好，我们的作品叫“筑生”。

筑生让每栋房子从开工第一天，就拥有一个会成长的AI智能体：建造时帮助工友把房子建好，入住后继续为住户、物业和企业服务。

我们的主题是：从开工第一天，到入住每一天。

## 0:25–0:55｜核心矛盾

一栋建筑可以使用几十年，但大量建造知识往往在交付时失去连续性。

工友需要重复填报，质量投入藏在文件里；住户遇到问题时，物业仍然要翻资料、敲墙体、找责任；同类问题解决之后，也很难自动变成下一栋房子的改进。

所以我们提出一个问题：能否让建筑像一个生命体一样，记得自己如何被建造，并在入住后继续感知、行动和成长？

## 0:55–1:40｜总体架构

筑生的核心是“一楼一脑，一事一专”。

每栋建筑拥有一个总智能体，负责四件事：保存长期记忆、分配专业任务、协调人和设备的权限、向管理者汇总改进建议。

总智能体之下，是建造期和入住期的专业智能体。

建造期有品质、项目协同和工友服务智能体；入住期有建筑健康、设备具身和居住服务智能体。

它们共享同一份建筑生命记忆：BIM、模块身份、施工证据、工友贡献、传感器状态和维修结果，都关联到具体空间和构件。

## 1:40–2:05｜生命周期

在建造阶段，建筑总智能体建立身体地图，工友用语音和照片完成可信留痕。

交付不是数据使命的结束，而是建筑服务能力的开始。

入住后，传感器成为感觉，建造记忆成为身体认知，专业智能体负责判断，阀门和设备成为行动能力。

每次真实运营结果，又会反哺下一批建筑。

## 2:05–3:35｜样板演示

下面我们不用第二个概念，只用一条卫生间渗漏链路，证明总体架构可以跑通。

首先进入工友端。工友扫描1602卫生间模块，通过语音和照片提交管线接头、防水和闭水试验。品质智能体自动关联空间、材料和验收要求，建筑由此记住自己的水系统。

现在切换到入住阶段。湿度传感器发现墙体持续异常，建筑总智能体立即调用建筑健康智能体，同时查询建造期留下的证据。

但它不会直接下结论。系统发现还缺少水表状态和墙面照片，于是向住户补充提问。

信息补齐后，系统排除洗浴导致的短时潮湿，把疑似漏点定位到墙内支管接头，并展示判断依据。

关闭阀门会影响住户用水，所以设备具身智能体必须等待人类授权。

住户确认后，局部阀门关闭，物业同步收到包含漏点坐标、内部构造、材料和维修建议的精准工单。

维修完成后，系统继续验证湿度回落。最终原因写回建筑记忆，并自动形成下一批MiC卫生间模块的工艺建议。

## 3:35–4:20｜AI协同与可靠性

这个过程中，AI不是一个聊天窗口。

总智能体完成任务规划，品质智能体读取建造记忆，建筑健康智能体分析时序和空间，设备具身智能体负责行动；住户和物业保留授权权利。

证据不足时不猜，专业结论冲突时转人工，高影响动作必须授权，设备失败时自动回退到人工方案。

因此它既体现多智能体协同，也保留了工程场景需要的安全边界。

## 4:20–4:50｜三方价值

对人民，筑生让住宅质量可查询、问题可解释、维修少走弯路。

对工友，它减少重复填表、返工和责任争议，也让关键工序贡献被长期记录。

对企业，它把现有数字建造能力延伸到交付和资产运营，降低质量与维保沟通成本，并沉淀材料、工艺和运营结果之间的数据资产。

## 4:50–5:00｜收尾

水系统只是筑生跑通的第一条生命链路。

我们希望中国建筑国际未来交付的不只是一栋好房子，而是一栋记得如何被建造、懂得如何服务人民、还能持续成长的建筑。

筑生，从开工第一天，到入住每一天。
